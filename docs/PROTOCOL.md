# Спецификация форматов ввода, вывода и конвейера синхронизации

## Цели

Обеспечить строгое соответствие выходных данных приложения формату автоматизированной проверки экспертов **Nuclear IT Hack** (стр. 14–15 презентации задания), а также детерминированную синхронизацию временных меток между модулем диаризации и модулем распознавания речи.

---

## Входные данные

1. **Импорт из локального хранилища Android:** Через системный Storage Access Framework (`Intent.ACTION_OPEN_DOCUMENT`) поддерживаются файлы `.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.opus`, `.flac`, `.amr`, `.mp4`.
2. **Запись из интерфейса приложения:** Встроенный диктофон (`AudioRecord`, 16 000 Гц, моно, PCM 16 бит).
3. **Встроенные реальные тестовые записи:** Три живые аудиозаписи русскоязычных диалогов из открытых датасетов (`assets/samples/`), доступные в один клик с главного экрана.

---

## Формат JSON-вывода (обязательный по ТЗ)

Экспортируемый JSON-файл содержит корневой объект с массивом `transcript`. Каждый элемент массива описывает одну реплику:

| Поле | Тип | Описание |
|---|---|---|
| `speaker_id` | `string` | Канонический идентификатор говорящего в порядке первого появления в диалоге (`"speaker_1"`, `"speaker_2"`, `"speaker_3"`, ...) |
| `start_ms` | `integer` | Время начала реплики от начала аудиозаписи в миллисекундах (`>= 0`) |
| `end_ms` | `integer` | Время окончания реплики от начала аудиозаписи в миллисекундах (`> start_ms`) |
| `text` | `string` | Распознанный текст реплики на русском языке с восстановленной пунктуацией и заглавными буквами |

### Пример выходного файла

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1112,
      "end_ms": 1720,
      "text": "Алло?"
    },
    {
      "speaker_id": "speaker_2",
      "start_ms": 3080,
      "end_ms": 9400,
      "text": "Алло, здравствуйте. Я говорю с Ольгой."
    }
  ]
}
```

## Синхронизация временных меток и определение границ реплик

1. **Единая шкала времени:** После декодирования и ресемплинга аудио приводится к частоте дискретизации $f_s = 16\,000\text{ Гц}$, где каждый отсчёт с индексом $k$ однозначно соответствует времени $t = \lfloor k \cdot 1000 / 16000 \rfloor\text{ мс}$.
2. **Сегментация речевых окон:** Детектор `Silero VAD` выделяет интервалы речи $[s_i, e_i]$. При передаче каждого окна в `GigaAM v3 RNN-T` относительные временные метки токенов $\tau_j$ переводятся в абсолютные координаты записи: $T_j = s_i + \lfloor 1000 \cdot \tau_j \rfloor$.
3. **Сопоставление со спикерами:** Для каждого собранного слова $[w_{\text{start}}, w_{\text{end}}]$ вычисляется суммарное пересечение с сегментами диаризации $[d_{\text{start}}, d_{\text{end}}]$ каждого кластера $c$:
   $$\text{overlap}(w, c) = \sum_{d \in D_c} \max\bigl(0,\, \min(w_{\text{end}}, d_{\text{end}}) - \max(w_{\text{start}}, d_{\text{start}})\bigr)$$
   Слову назначается спикер с максимальным перекрытием (или ближайший по времени при отсутствии прямого перекрытия).
4. **Медианная фильтрация и группировка:** Одиночные короткие слова (< 450 мс) без пауз (< 300 мс), окружённые с обеих сторон одним и тем же спикером, сглаживаются. Соседние слова одного спикера объединяются в реплику до смены говорящего или длительной паузы (> 1500 мс, либо > 850 мс на границе предложения).
